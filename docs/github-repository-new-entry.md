# GitHub 仓库预选新建会话入口

## 概述

本方案为 Projects 和置顶仓库区域补充统一的新建会话入口。入口复用现有仓库标题组件与仓库选择能力，使用户可以从指定 GitHub 仓库直接进入已预选仓库的新建页，同时避免提前创建空会话。

## 实现方式

### 复用导航与仓库操作组件

- 复用仓库标题组件，Projects 和置顶区共用菜单及新建入口。
- 保留原有置顶处理、归档数量预览和归档确认流程。
- 点击菜单操作不会触发仓库展开。
- 移动端完成新建导航后关闭侧栏。

### 基于现有创建能力开发

- 基于最新 `upstream/main` 的 `d412b15c` 开发。
- 该版本已提供 `createConversation(repositories)` 和仓库选择器。
- 初次调查中“接口仅接收 `title`”的结论只适用于当时的旧工作树，本轮不再适用。
- 本次仅调整前端，不修改 Portal 或 AgentAPI。

### GitHub 仓库预选

- 新建入口仅用于现有选择器支持的 GitHub 仓库。
- 点击入口后导航至仓库预选的新建会话输入页。
- 根据实际 GitHub App 安装列表解析 `installation_id` 和 `full_name`，不依赖猜测或拼接安装信息。
- 用户发送消息时才复用原有创建接口，不在进入页面时提前创建空会话。

### 状态与权限处理

- 安装列表加载期间，阻止尚未关联仓库的消息发送。
- 用户无目标仓库权限时，同样阻止未关联发送。
- 切换目标仓库时同步更新当前选择。
- 切换仓库不会清空草稿，并保留从 Settings 往返后的页面状态。

## 仓库摘要展示

新建页展示仓库名称与远程地址摘要卡片，视觉样式与现有 Issue/PR 卡片保持一致。

远程地址仅使用系统已知的仓库地址，不推测或生成未知地址。

## 范围边界

本次实现不包含以下能力：

- 目录编辑；
- worktree 创建或管理；
- 非 GitHub 仓库的新建入口；
- Portal 或 AgentAPI 接口调整。
